# انتقال استاتیک گزارش‌ها به Vue

## هدف

نمای گزارش‌های فعلی کلینیک از فایل مستقل `Frontend/public/reports/index.html` به رابط کاربری بومی Vue منتقل شود؛ خروجی باید از نظر ظاهر و رفتارهای محلی با صفحهٔ موجود یکسان باشد، ولی بدون iframe بارگذاری شود.

## محدودهٔ این مرحله

- صفحهٔ گزارش فعلی به اجزای Vue قابل نگهداری منتقل می‌شود.
- CSS، فونت‌های وزیر، رنگ‌ها، فاصله‌ها، نمودارها، تب‌ها، پنل فیلتر، جدول‌ها و کنترل‌های محلی فعلی حفظ می‌شوند.
- `Gozaresh.vue` به جای iframe کامپوننت گزارش بومی را نمایش می‌دهد.
- داده‌های نمونه‌ای که اکنون صفحه را تغذیه می‌کنند، در این مرحله همان‌گونه ثابت می‌مانند تا ظاهر و همهٔ تعامل‌های رابط کاربری بدون وابستگی به API قابل بررسی باشند.
- فایل‌ها و مسیرهای تصویری مورد نیاز به شیوه‌ای که Vite پشتیبانی می‌کند در Vue استفاده می‌شوند.

## خارج از محدودهٔ این مرحله

- اتصال کارت‌ها، جدول‌ها، نمودارها یا خروجی CSV به API واقعی.
- تغییر محاسبهٔ حقوق پزشکان و پرسنل یا APIهای فعلی تسویه.
- بازطراحی، ساده‌سازی یا تغییر چیدمان صفحه.
- حذف فایل قدیمی `public/reports`؛ فایل قدیمی تا زمان تأیید برابری بصری نگه داشته می‌شود.

## معماری

یک کامپوننت ریشهٔ گزارش و اجزای کوچک‌تر برای نوار تاریخ/فیلتر، کارت‌های آماری، جدول‌ها و نمودارهای موجود ایجاد می‌شود. وضعیت‌های محلی فعلی (تب انتخاب‌شده، فیلترها، ترتیب جدول‌ها و باز/بسته‌بودن داشبوردها) به state واکنشی Vue منتقل خواهند شد. `Gozaresh.vue` فقط میزبان این کامپوننت خواهد بود و منطق تغییر اندازهٔ iframe حذف می‌شود.

## معیار پذیرش

1. انتخاب منوی گزارش، بدون iframe صفحهٔ گزارش را نشان می‌دهد.
2. صفحه در دسکتاپ و موبایل با طرح فعلی هم‌خوان است؛ فونت و تصویرها درست بارگذاری می‌شوند.
3. کنترل‌های تعاملی فعلیِ مستقل از سرور (تب‌ها، فیلترها، مرتب‌سازی‌ها و نمایش/پنهان‌سازی داشبوردها) کار می‌کنند.
4. اجرای build فرانت‌اند بدون خطا تمام می‌شود.
5. در این مرحله هیچ درخواست API جدیدی از صفحهٔ گزارش ارسال نمی‌شود.

## ادامهٔ کار

پس از تأیید برابری ظاهری، زیرپروژهٔ بعدی کارت‌ها و جدول‌های «حقوق پزشکان و پرسنل» را به API گزارش حقوق متصل می‌کند و دادهٔ نمونهٔ همان بخش را حذف می‌کند.
